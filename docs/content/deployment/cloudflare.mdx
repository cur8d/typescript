# Cloudflare Workers Deployment

Cloudflare Workers provides edge compute and static asset hosting for your application and documentation with global distribution on Cloudflare's network.

## Architecture

Cur8d uses **OpenNext for Cloudflare** (`@opennextjs/cloudflare`) to compile the Next.js App Router application into a Cloudflare Worker:

- **Server Logic & SSR**: Runs inside a Cloudflare Worker with `nodejs_compat` runtime compatibility.
- **Static Assets**: Hosted on Cloudflare's global edge network via Workers Static Assets (`.open-next/assets`), serving images, fonts, and client bundles with zero worker execution overhead.
- **Documentation**: Static documentation generated by Nextra can be deployed to Cloudflare Workers using native static asset hosting (`docs/out`).

## Configuration

Cloudflare Workers settings and bindings are maintained in:

- [`wrangler.json`](../../../wrangler.json): Configures the main application Worker, entry point (`.open-next/worker.js`), build command (`opennextjs-cloudflare build`), Worker previews (`previews`), compatibility date and flags (`nodejs_compat`), and static assets directory (`.open-next/assets`).
- [`open-next.config.ts`](../../../open-next.config.ts): OpenNext build configuration for Cloudflare adapter optimizations.
- [`docs/wrangler.json`](../../../docs/wrangler.json): Configures the documentation Worker using native static assets (`docs/out`).

### Cloudflare Workers Builds (Git Integration)

When connecting your GitHub repository to Cloudflare Workers Builds for automated continuous deployment on push/PR:

- **Build command**: `pnpm run build:worker` (or `mise run build:worker`)
- **Deploy command**: `npx wrangler deploy` (production) / `npx wrangler preview` (previews)

## Automated CI/CD Deployment

Cloudflare deployment is configured in `.github/workflows/deploy.yml`:

- Can be triggered on-demand via `workflow_dispatch` selecting the `cloudflare` provider.
- Deploys preview or production environments to Cloudflare Workers based on the specified environment.

### Setting up Secrets in GitHub

To enable automated deployments via GitHub Actions:
1. Log in to the [Cloudflare Dashboard](https://dash.cloudflare.com).
2. Retrieve your Account ID from the **Workers & Pages** overview or the dashboard sidebar.
3. Generate an API token with **Cloudflare Workers Edit** permissions under **My Profile** > **API Tokens**.
4. Add the following repository secrets under `Settings > Secrets and variables > Actions`:
   - `CLOUDFLARE_API_TOKEN`: Your Cloudflare API token.
   - `CLOUDFLARE_ACCOUNT_ID`: Your Cloudflare account ID.

## Local Deployment via mise

You can build and deploy to Cloudflare Workers directly from your terminal using `mise` or `pnpm`:

```bash
# Deploy to Cloudflare Workers (preview)
export CLOUDFLARE_API_TOKEN="your_token"
export CLOUDFLARE_ACCOUNT_ID="your_account_id"
export CLOUDFLARE_ENV="preview"
mise run deploy:cloudflare

# Deploy to Cloudflare Workers (production)
export CLOUDFLARE_ENV="production"
mise run deploy:cloudflare

# Or using package.json scripts directly
pnpm run deploy:cloudflare
pnpm run deploy:cloudflare:docs
```
